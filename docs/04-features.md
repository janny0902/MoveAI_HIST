## 2. 기사 게이트

1. 로그인 — 차량번호 + 전화
2. 프로필 — 톤수, 차종, 잔여%
3. 경로 — 작업터미널 코드 (기본 200→001)
4. 앱 — 하단 **배차목록 / 운행 / 정산**

세션: `sessionStorage` `moveai_session`  
운행 유지: `localStorage` `moveai_active_trip_{truckId}`  
시연 리셋 epoch가 바뀌면 운행·장바구니를 비운다.

## 3. 기능

### F-01 로그인/프로필/경로
신규 트럭 생성. `needProfile`, `needRoute`.

### F-02 배차목록
- 터미널 핀 · `groups-by-terminal` (PENDING + 잔여 가능)
- 장바구니 담기 · 미리보기 도로 경로 (기존 담기 유지)
- LLM 최적배차 → 추천만 담고 확정은 별도
- **배차 확정** = accept-batch → 운행 시작 (5경유 등)

### F-03 운행 지도
- 카카오 polyline + 정류장
- 하단 출도착: 현재 정차 → 다음 도착
- 상차 사진 후 **도착지로 출발** / **도착지에 도착**
- 지도 `>` : 내비 경로를 20km 보간 이동 (기사 핀)

### F-04 상차·적재 UI
- 계획 적재(터미널별) + 실측(사진 Δ)
- 경유 스톱을 숨기지 않음 (출발·경유·도착 모두)
- 깊이는 천장 말고 **바닥** 기준
- 표시 채움은 실측만 (계획%는 별도)

### F-05 운행 중 복화 토스트
조건 (모두):
- 현재 핀 기준 **≤ 20km**
- 도착이 **같은 권역** (서울 001/008, 부산 200/201)
- 물량 fill% ≤ **계획 잔여** (`100 − 계획적재합`, 실측이 더 크면 실측)
- PENDING

동작:
- 토스트 유지(반경 밖이면 닫힘) · **수락** 버튼
- 핀에 터미널명·fill%
- 이미 수락한 origin은 다시 제안하지 않음

### F-06 토스트 수락
- 계획 적재에 fill 합산 (리스트·상단 % 즉시 반영)
- 잔여 부족이면 수락 거부 (`INSUFFICIENT_SPACE`)
- 경유 **이미 있으면** 물량만 더함
- 없으면 **최종 도착 바로 앞**에 삽입 (부산→김천→부산 방지)
- 기존 stopIndex · 실측 · 시뮬 위치 유지
- `POST /api/dispatch/restitch-route` 로 도로선만 재계산

### F-07 정산
수락 건별 수입/유류비/순익/ESG.

### F-08 시연 리셋
`POST /api/dispatch/demo-reset` — OD 재시드, 전 차량 공차, 정산 비움.  
기사 앱은 epoch를 보고 운행·카트를 지운다.

### F-09 관리자 적재 배정
`/admin` — 차량 용량 대비 CBM/중량. **기사 위치 디스패치가 아님.**
