## 1. 시나리오 (지금 시연)

1. 11톤 기사가 **부산→서울** 간선 경로를 잡고 배차목록에서 물량을 장바구니/최적배차로 담아 **배차 확정**.
2. 운행 탭에서 상차 사진을 올리면 **적재율·잔여%** 를 계산해 실측으로 쌓는다.
3. 지도 `>` 로 내비 경로를 **20km씩** 이동한다.
4. 현재 위치 **20km 안**, **같은 도착 권역**, **계획 잔여**에 들어가는 PENDING 물량만 토스트+핀.
5. **수락**하면 계획 적재에 더하고, 지금 출도착은 유지한 채 **최종 도착 앞**에 경유를 끼운 뒤 도로 경로를 다시 잇는다.
6. 계획이 이미 꽉 차면(예: 90%) 50% 물량은 제안하지 않는다.
7. 정산에서 수입·유류비·순이익·ESG를 본다.

## 2. 기능 요구 ↔ MVP

| # | RFP | 현재 |
|---|-----|------|
| 1 | 상차 사진 | 파일 업로드 (시연) |
| 2 | 적재/잔여 계산·DB | Depth + OpenCV + Gemini 융합 → `trucks` / `load_history` |
| 3 | 외부 복화요청 | 데모 OD 시드 + `propose` + 터미널 그룹 |
| 4 | 여유 차량 선별 | 잔여% · 동일 도착 권역 · fill ≤ 계획잔여 |
| 5 | 비용·이익·거리 | CalculationService + Kakao Navi |
| 6 | 승낙/거절 | 장바구니 확정 · 토스트 수락 · dismiss |
| 7 | 거절 시 강제 재제안 없음 | PENDING 유지 |
| 8 | 수락 시 경로·ETA | 카카오 stitch + 도착시각·추가 분 |
| 9 | 상차마다 재촬영 | 정차마다 사진, 계획+실측 리스트 |
| 10 | 완료 후 수익·ESG | 정산 탭 |
| + | Tail 로깅 | 처리 과정 |
| + | 운행 중 복화 | 20km 토스트 · 수락 · 경유 삽입 |
| + | 과적 방지 | 계획 적재 합이 잔여를 넘으면 미제안 |
